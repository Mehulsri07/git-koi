# Pond Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in 832×384 pond banner where the koi swims a racetrack
under lilypads, one per owned public repository, sized by the owner's commits.

**Architecture:** Collection records owned repositories and the owner's commit
counts in a new snapshot version 4. A new pure `pond` module turns the snapshot
into a `PondLayout`. The renderer gets a variable canvas, a racetrack course,
and a pad layer drawn above the koi. The GIF encoder writes one base frame of
pads, then frames that store only what differs from the base. Without `--pond`,
every output stays byte-identical.

**Tech Stack:** Rust 2024 edition at the crate's `rust-version`, `gif` 0.14,
`png` 0.18, `serde`, `chrono`, and the GitHub CLI for collection. No new
dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-pond-design.md`

## Global Constraints

- Pond canvas: 416×192 native pixels, exported at `STATIC_EXPORT_SCALE` (2), so
  832×384.
- Pad diameters by size 1–5: 16, 24, 32, 40, 48 native pixels.
- Size boundaries by the owner's commits: ≤10 → 1, 11–20 → 2, 21–40 → 3, 41–80 →
  4, 81+ → 5.
- At most 12 pads: the most commits first, ties to the lower repository ID.
- Flowers: the biggest pad of language rank 1 is `Pink`, rank 2 `White`, rank 3
  `Purple`. The biggest pad of each language ranked 4 or lower gets a `Bud`.
  Rank goes by pad count, ties by language name. Ties for the biggest pad go to
  the lower repository ID.
- Pond colors come only from the spec's Palette section.
- Every frame has at most 255 opaque colors and no partially transparent pixel.
- Pond GIF for a maximum koi (100,000 contributions) with 12 size-5 pads: under
  1,000,000 bytes.
- Base GIF frame delay: 2/100 s.
- Pond cruise and dart loops: 180 frames at `FRAMES_PER_SECOND` (15). Cruise
  makes 1 lap, dart 2.
- Without `--pond`, the outputs for the existing fixtures are byte-identical to
  1.0.2.
- Every gate in `.github/workflows/ci.yml` passes: rustfmt, Clippy with
  `-D warnings`, tests, the release build, rustdoc with `-D warnings`, and
  `npx prettier@3.9.10 --check .`.
- Commit subjects use `area: lowercase imperative phrase` (CONTRIBUTING.md), and
  each commit ends with the session's attribution lines.
- Tests sit at public boundaries in `tests/*.rs` and fail under the bug they
  name.

## Review Focus

   still swims, and the GIF is still valid. Test in Task 3 and Task 7.
2. A repository with no default branch (an empty repository) has 0 commits and
   size 1, and collection does not fail. Test in Task 2.
3. A single-repository account whose repository has no language gets one plain
   pad with no flower. Test in Task 3.
4. A deep-resting koi (depth 1) under pads stays tinted while the pads do not,
   and frames stay at or under 255 colors. Test in Task 6.
5. A pond render from a v3 snapshot fails with the exact re-collect message and

### Task 3: Pond layout

**Files:**

- Create: `src/pond.rs`

**Interfaces:**

- Consumes: `AccountSnapshot`, `RepositoryObservation`, `OwnedRepository`.
- Produces:

```rust
pub const POND_WIDTH_PIXELS: u32 = 416;
pub const POND_HEIGHT_PIXELS: u32 = 192;
pub const MAX_PADS: usize = 12;
#[derive(Clone, Copy, Debug, Eq, PartialEq, Ord, PartialOrd)]
pub struct PadSize(u8); // 1..=5
impl PadSize {
    pub fn from_commits(owner_commit_count: u64) -> Self;
    pub fn level(self) -> u8;
    pub fn diameter_pixels(self) -> u32;
    pub fn smaller(self) -> Option<Self>;
}
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum Bloom { Pink, White, Purple, Bud }
#[derive(Clone, Debug, PartialEq)]
pub struct Pad {
    pub repository_id: u64,
    pub center: [f64; 2],          // native pixels, origin top left
    pub size: PadSize,
    pub bloom: Option<Bloom>,
    pub notch_radians: f64,
}
#[derive(Clone, Debug, Default, PartialEq)]
pub struct PondLayout { pub pads: Vec<Pad> }
#[derive(Debug, Eq, PartialEq)]
pub enum PondError { NoOwnedRepositories, ConflictingRepository(ConflictingRepository) }
pub fn layout_pond(account_snapshot: &AccountSnapshot) -> Result<PondLayout, PondError>;
```

`PondError::NoOwnedRepositories` means `owned_repositories` is `None`, and its
`Display` text is exactly
`the pond needs a snapshot collected by git-koi 2.0; run git-koi collect again`.
`PondError` implements `Display` and `Error`. An empty `Some(vec![])` is not an
error; it gives an empty layout.

```text
order pads by size descending, then repository ID ascending
for each pad:
  size = its PadSize
  loop:
    for attempt in 0..64:
      h = splitmix64(account_id ^ repository_id.rotate_left(17) ^ attempt)
      if size ≤ 2 and a placed pad of size ≥ 4 exists and attempt is even:
        anchor = the placed pad with the lowest ID among size ≥ 4
        candidate = anchor.center + polar(r_anchor + r + 3 + (h % 9), angle from h)
      else:
        candidate = (r + (h % (416 − 2r)), r + ((h >> 32) % (192 − 2r)))
      accept the first candidate inside the pond with every gap ≥ 2
    if accepted: place, break
    size = size.smaller(), or else drop the pad
notch_radians = (splitmix64(repository_id) % 6283) / 1000
```

Write `splitmix64` as a private function in `pond.rs`.

- Drawing rules (procedural; the palette's exact values are in the spec):
  - Each pad is a disc of radius `d/2` with a wedge notch of ±0.32 rad at
    `notch_radians`. The edge is 1 pixel of the darkest shade, and the body is
    shaded by `(−dx − dy)/(r√2)` into base, shade and highlight bands.
  - Veins: five spokes from the center in the mid shade.
  - Sizes 4–5 get two droplets: 2×2 in the light teal, with a 1-pixel `#a8e3e6`
    highlight.
  - The ripple is a 1-pixel arc at `r + 3` over 140°, opposite the notch, in
    `#6fb3b8`.
  - A lotus is a 4-fold petal ring of radius `0.3 d`, at least 4 pixels, using
    the bloom's 4 colors with the pollen center. A bud is a 3×5 closed pink bud.

### Task 7: Base-plus-difference GIF encoding

- Produces:
  `pub fn encode_pond_gif(base: &KoiFrame, frames: &[KoiFrame]) -> Result<Vec<u8>, GifEncodingError>`.
  - Frame 0 is the base: the box around its drawn pixels,
    `DisposalMethod::Keep`, delay 2.

    `calculate_elapsed_hundredths`.

    frame, it fails with the new
    `GifEncodingError::PondPixelCleared { frame_index }`. That can't happen when
    pads are drawn above the koi.
